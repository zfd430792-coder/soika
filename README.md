## Установка

**На сервере (Debian/Ubuntu) — одной командой:**

```bash
wget -qO- https://raw.githubusercontent.com/zfd430792-coder/soika/main/install.sh | sudo bash
```

Скрипт поставит зависимости, соберёт venv, создаст systemd-сервис и запустит его.
Дальше открываешь логи — там ссылка на веб-установщик:

```bash
journalctl -u soika -f
```

Вводишь `api_id` и `api_hash` с [my.telegram.org/apps](https://my.telegram.org/apps),
заходишь по QR-коду — всё. Сойка сама заведёт инлайн-бота и пришлёт приветствие.

<details>
<summary><b>Локально, для разработки модулей</b></summary>

```bash
python -m venv venv
venv/bin/pip install -r requirements.txt
venv/bin/python -m soika
```

При первом запуске Сойка спросит ключи и нарисует QR-код прямо в терминале.
</details>

<details>
<summary><b>Аргументы запуска</b></summary>

| Аргумент | Что делает |
|---|---|
| `--data-root ПУТЬ` | где хранить сессии, базу и модули |
| `--phone +7...` | вход по номеру вместо QR |
| `--no-web` | не поднимать веб-интерфейс |
| `--web` | держать веб-панель включённой постоянно |
| `--port 8080` | порт веб-панели |
| `--proxy socks5://...` | подключение через прокси |
| `--debug` | подробные логи |
</details>

<details>
<summary><b>Что происходит при первом запуске</b></summary>

1. **Ключи.** В логах ссылка на веб-установщик с одноразовым токеном. Ключи
   лягут в `config.json` рядом с кодом и никуда не уйдут.
2. **Вход.** QR-код на той же странице — сканируешь в Telegram (Настройки →
   Устройства → Подключить устройство). Есть двухфакторка — спросит пароль.
3. **Инлайн-бот.** Сойка сама сходит к BotFather, заведёт бота `soika_xxxxxx_bot`,
   поставит аватарку и напишет ему `/start` за тебя.
4. **Приветствие.** Бот пришлёт баннер, гайд и кнопки меню. Там же спросит про
   бэкап — молча ничего не включается.
5. **Готово.** Пиши `.help` в любом чате. Веб-панель дальше не нужна.
</details>

## Возможности

- 🧩 **14 модулей и 63 команды встроено** — после входа всё уже работает
- 🔁 **Модули от Hikka, FTG, GeekTG и Dragon** ставятся без правок
- 🤖 **Свой инлайн-бот** заводится сам — кнопки, галереи, вывод ошибок. После
  внезапного перезапуска отмечается одной строкой, по команде — молчит
  (`.cfg` → **Бот** → `announce_restart`)
- ⚙️ **Настройки кнопками** — `.cfg` вместо правки файлов
- 🗄 **Бэкапы базы** по расписанию в отдельный канал, восстановление одной командой
- 📜 **Логи** в служебный канал и файлом по команде
- 🔄 **Обновления** — сама следит, пишет в бота что вышло, кнопка «Обновить»
- 🔐 **Права** по маскам: владелец, sudo, админы чата, все подряд
- 🌐 **Веб-установщик** на время первого входа, дальше не мешается
- 🇷🇺 **Два языка** — русский и английский, переключаются кнопкой

**Мелочи, которые экономят нервы:** `.реды` сработает как `.help` — раскладка
исправляется сама; `..help` не выполнится — двойной префикс экранирует команду;
`.modules | grep loader` отфильтрует вывод любой команды; `.help@username`
адресует команду конкретному аккаунту, если их несколько.

🌟 Владелец: Имя ← ссылка на профиль
✍️ Префикс: «.»

<details>
<summary><b>Как приходят обновления</b></summary>

Сойка проверяет репозиторий сама — первый раз через две минуты после запуска,
дальше раз в час. Нашла новую версию — пишет в личку своего бота:

```
[баннер]

🪶 Вышло обновление Сойки

🕸 Версия: 1.6.2 → 1.7.0
📦 Новых коммитов: 2

📝 Что изменилось:
▫️ Каталог модулей переехал в отдельный репозиторий
▫️ Кнопка «Открыть канал» открывает канал, а не браузер

[⬇️ Обновить]  [🚫 Позже]
[📖 Коммиты]
```

Нажал «Обновить» — подтянет изменения, поставит зависимости, перезапустится и
**перепишет это же сообщение** на «✅ Сойка обновлена: 1.11.1 → 1.11.2». Новых
сообщений не появляется, список изменений второй раз не показывается.
С `.autoupdate` то же самое без вопросов.
</details>

## Модули

Всё нужное встроено, доставлять ничего не надо. Дополнительные модули и
руководство, как писать свои, живут в отдельном репозитории:

### 👉 [Soika-modu](https://github.com/zfd430792-coder/Soika-modu)

```
.ml counter          поставить из каталога
.dlmod <ссылка>      поставить по ссылке
.loadmod             поставить .py файл (ответом на него)
```

В руководстве — от «модуля за пять минут» до чек-листа и разбора частых ошибок,
плюс рабочие примеры `template.py` и `counter.py`.

Модули, написанные под Hikka, FTG, GeekTG и Dragon, ставятся без правок — слой
совместимости подменяет им имена пакетов на лету.

> ⚠️ **Чужие модули ставь с оглядкой.** Модуль — это код, который выполняется от
> имени твоего аккаунта: он видит переписку, может писать от тебя, читать базу
> Сойки и уносить наружу что угодно, включая сессию и токен бота. Никакой
> песочницы нет — так устроены все юзерботы.
>
> - ставь только то, чьему автору доверяешь, а не первое, что скинули в чате;
> - перед установкой открой `.py` и посмотри, что он делает: чужие адреса,
>   отправку файлов, обращения к `config.json`, сессии или `bot_token`;
> - «модуль для накрутки/взлома/бесплатного премиума» — это способ увести
>   аккаунт, а не полезная команда;
> - поставил лишнее — `.unloadmod имя`, а если успел запуститься чужой код,
>   меняй пароль, сбрасывай сессии в Telegram и перевыпускай токен `.revokebot`.

## Доступ для других

По умолчанию юзерботом управляешь только ты. Дальше — по возрастанию доверия:

| Что нужно | Как |
|---|---|
| дать другу **одну команду** | `.allow ping` ответом на его сообщение |
| открыть команду **всем в чате** | `.allow ping чат` |
| открыть команду **всем подряд** | `.security ping everyone` |
| дать другу **обычные команды** | `.sudo` ответом на него |
| сделать **совладельцем** | `.owner` ответом на него |

`.rules` покажет выданные точечные разрешения, `.deny` заберёт их, а повторный
`.sudo` или `.owner` на том же человеке уберёт его из списка.

**Доступ на время:** `.allow ping 2h` — правило само истечёт. Понимает `30m`,
`2h`, `7d`; `.rules` показывает, сколько осталось.

**Кнопками:** `.security <команда>` открывает панель, где каждая группа прав —
переключатель. `.security` без аргументов — глобальный потолок: что бы ни просил
модуль, выше этой планки команда не поднимется.

Где Сойка **не** должна работать: `.blacklist` в чате — и она молчит там
совсем, `.blacklistuser` ответом на человека — не слушает его команды,
`.suspend 300` — замолкает везде на пять минут.

> ⚠️ `.sudo` — это доверие целиком: такой человек может ставить модули, а значит
> выполнять произвольный код от имени твоего аккаунта. `.owner` вдобавок открывает
> `.e`, `.shell`, бэкапы и перезапуск. Для друга, которому нужен только `.ping`
> или пара безобидных команд, правильный путь — `.allow`, а не `.sudo`.

## Служебные каналы

Сойка заводит их сама при первом запуске и глушит, чтобы не мешались.

| Канал | Что внутри |
|---|---|
| `soika-logs` | ошибки и предупреждения потоком |
| `soika-backups` | копии базы по расписанию, последние 20 |
| `soika-assets` | файлы модулей |

<details>
<summary><b>Бэкапы подробнее</b></summary>

При первой установке Сойка **спрашивает**, как настроить бэкап, — молча ничего
не включает. Карточка с кнопками открывается командой `.backups`: режим (каждый
день / раз в N часов / выключить), время, куда складывать и кнопка «Сделать
бэкап сейчас».

По умолчанию — каждый день в 03:00 по времени сервера в `soika-backups`.
Текстом то же самое: `.autobackup 03:30`, `.autobackup 6h`, `.autobackup off`.

Восстановление — `.restoredb` ответом на файл копии. Перед перезаписью текущая
база откладывается в `db-<id>.json.rev1`, так что откатиться можно всегда. Свой
инлайн-бот при этом остаётся: токен из файла не подставляется.
</details>

## Устройство

<details>
<summary><b>Из чего собрана</b></summary>

```
soika/
├── main.py          запуск, аккаунты, главный цикл
├── auth.py          QR-логин, вход по номеру, 2FA, сессии
├── client.py        Telethon-клиент с кэшем сущностей
├── database.py      JSON-база с атомарной записью и ревизиями
├── loader.py        загрузка модулей, декораторы, зависимости
├── dispatcher.py    разбор команд, фильтры, ratelimit, grep
├── security.py      owner / sudo / support и маски прав
├── translations.py  языковые паки и строки модулей
├── compat.py        совместимость с чужими модулями
├── inline/          свой бот: формы, галереи, списки, ЛС
├── web/             веб-установщик и панель
└── modules/         встроенные модули
```

Данные — сессии, `config.json`, `db-<id>.json`, `loaded_modules/` — лежат рядом
с кодом и в git не попадают. Каталог переносится аргументом `--data-root`.

Баннеры лежат в [`assets/`](assets/) и собираются одним скриптом:
`python assets/make_banners.py`.
</details>

## Вопросы и ответы

<details>
<summary><b>Забанят ли аккаунт?</b></summary>

Юзерботы Telegram не приветствует. Риск снижают простые вещи: не спамить, не
раздавать `.sudo` посторонним и не ставить на аккаунт, который жалко потерять.
</details>

<details>
<summary><b>Нужен ли свой сервер?</b></summary>

Нет, но с ним удобнее — юзербот работает, только пока запущен процесс. Подойдёт
любая VDS, Termux на телефоне или домашний компьютер.
</details>

<details>
<summary><b>Что если инлайн-бот не создался?</b></summary>

У BotFather лимит 20 ботов на аккаунт. Удали лишнего и перезапусти Сойку — она
попробует снова. Состояние показывает `.botinfo`, причину — `.logs error`.
</details>

<details>
<summary><b>Как перенести на другой сервер?</b></summary>

Скопируй каталог с данными: `config.json`, `soika-*.session`, `db-*.json`,
`loaded_modules/`. Всё состояние в них, заново входить не придётся.
</details>

<details>
<summary><b>Как посмотреть, что сломалось?</b></summary>

`.logs error` пришлёт файл с ошибками, а канал `soika-logs` копит их постоянно.
Упавшая команда присылает трейсбек прямо в чат.
</details>

<details>
<summary><b>Что важно знать про безопасность</b></summary>

- `api_id` и `api_hash` хранятся только в `config.json` на твоём сервере;
- веб-панель закрыта одноразовым токеном из логов — на сервере лучше закрыть
  порт фаерволом и ходить через SSH-туннель;
- `.e` и `.shell` выполняют произвольный код — держи их только для себя;
- файл бэкапа содержит токен бота и список доверенных, не пересылай его.
</details>
