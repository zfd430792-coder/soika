## Что это

Сойка — юзербот: он работает от имени твоего аккаунта и добавляет ему команды.
Написал в чате `.info` — увидел карточку с версией и нагрузкой. Написал
`.dlmod ссылка` — получил новую команду. Всё, что делает юзербот, делает как
будто ты сам.

Собрана на живом стеке — Telethon 1.44 и aiogram 3.30, Python 3.10 и новее.
Внутри ничего лишнего: JSON-база с атомарной записью, свой загрузчик модулей,
свой инлайн-бот и веб-установщик на время первого входа.

**Модули для Hikka, FTG, GeekTG и Dragon работают без правок** — слой
совместимости подменяет им имена пакетов на лету, так что тысячи уже написанных
модулей ставятся как есть.

## Возможности

**🧩 Модули.** 14 встроенных, 44 команды — после входа в аккаунт всё уже
работает. Чужие ставятся по ссылке, файлом или из каталога: `.dlmod`, `.loadmod`,
`.ml`. Зависимости модуль тянет себе сам через `# requires:`.

**🤖 Свой инлайн-бот.** Создаётся автоматически при первом запуске — токен просить
не надо. Через него работают кнопки, галереи, пагинация и вывод ошибок. Отвечает
только владельцу аккаунта, посторонних отбрасывает на входе.

**⚙️ Настройки кнопками.** `.cfg` открывает редактор конфигов: переключатели,
списки, ввод значений прямо в личке бота. Валидаторы не дадут записать ерунду.

**🗄 Бэкапы.** База копируется по расписанию в отдельный канал, хранятся последние
20 копий. Настраивается кнопками, восстанавливается одной командой.

**📜 Логи.** Ошибки уходят в служебный канал пачками, файлом их отдаёт `.logs`.
Уровень и частоту можно менять на ходу.

**🔄 Обновления.** Сойка сама проверяет репозиторий, пишет в бота, что вышло, и
показывает список изменений с кнопкой «Обновить». Может обновляться сама.

**🔐 Права.** Каждой команде — своя маска: только владелец, совладельцы, админы
группы, все подряд. `.sudo` выдаёт доступ конкретному человеку.

**🌐 Веб-установщик.** Первый вход — через браузер: ввёл ключи, отсканировал
QR-код, закрыл вкладку. Дальше панель не нужна и по умолчанию выключается.

**🇷🇺 Два языка.** Русский и английский, переключаются кнопкой или `.lang`.
Модули могут добавлять свои переводы через `strings_en`.

## Установка

### На сервере (Debian/Ubuntu) — одной командой

```bash
wget -qO- https://raw.githubusercontent.com/zfd430792-coder/soika/main/install.sh | sudo bash
```

Или, если репозиторий уже скачан:

```bash
sudo bash install.sh
```

Скрипт поставит зависимости, соберёт venv, создаст systemd-сервис `soika` и
запустит его. Дальше смотри логи:

```bash
journalctl -u soika -f
```

### Локально (для разработки модулей)

```bash
python -m venv venv
venv/bin/pip install -r requirements.txt
venv/bin/python -m soika
```

При первом запуске Сойка спросит ключи и нарисует QR-код прямо в терминале.

### Аргументы запуска

| Аргумент | Что делает |
|---|---|
| `--data-root ПУТЬ` | где хранить сессии, базу и модули |
| `--phone +7...` | вход по номеру вместо QR |
| `--no-web` | не поднимать веб-интерфейс |
| `--web` | держать веб-панель включённой постоянно |
| `--port 8080` | порт веб-панели |
| `--proxy socks5://...` | подключение через прокси |
| `--debug` | подробные логи |

## Первый запуск — по шагам

1. **Ключи.** В логах будет ссылка на веб-установщик с одноразовым токеном.
   Открываешь её, вводишь `api_id` и `api_hash` с
   [my.telegram.org/apps](https://my.telegram.org/apps). Они лягут в `config.json`
   рядом с кодом и больше никуда не уйдут.
2. **Вход.** На той же странице появится QR-код — сканируешь его в Telegram
   (Настройки → Устройства → Подключить устройство). Если включена двухфакторка,
   страница спросит пароль. Вместо QR можно войти по номеру: `--phone +7...`.
3. **Инлайн-бот.** Сойка сама сходит к BotFather, заведёт бота вида
   `soika_xxxxxx_bot`, поставит ему аватарку и напишет `/start` за тебя — чтобы
   диалог сразу появился в списке чатов.
4. **Приветствие.** Бот пришлёт баннер, короткий гайд и кнопки меню. Там же
   спросит, как настроить бэкап — молча ничего не включается.
5. **Готово.** Пиши `.help` в любом чате. Веб-панель поднимается только на время
   первого входа — держать её постоянно нужно лишь с флагом `--web`.

## Команды

Префикс по умолчанию — точка. Меняется командой `.prefix !`.

Всё нужное встроено: **14 модулей, 44 команды**. После входа в аккаунт ничего
доставлять не надо — [каталог](modules/) и `.ml` нужны только для дополнительных
модулей.

| Команда | Описание |
|---|---|
| `.help [модуль]` | список модулей или справка по одному |
| `.info`, `.ping` | карточка юзербота с баннером, задержка до Telegram |
| `.dlmod <ссылка>` | установить модуль по ссылке |
| `.loadmod` | установить модуль из .py файла (ответом на файл) |
| `.ml <имя>` | установить модуль из каталога |
| `.unloadmod <имя>` | выгрузить модуль |
| `.modules` | что установлено и откуда |
| `.cfg`, `.setcfg` | настройки модулей кнопками и текстом |
| `.prefix`, `.addalias`, `.delalias`, `.aliases`, `.lang` | префикс, алиасы, язык |
| `.e <код>` | выполнить Python-код прямо из чата |
| `.shell <команда>`, `.killshell` | команды системы с живым выводом |
| `.sudo`, `.support`, `.owner`, `.security` | кому и какие команды разрешены |
| `.id` | ID чата, сообщения и пользователя |
| `.note`, `.notes`, `.delnote`, `.clearnotes` | короткие заметки в базе юзербота |
| `.botmenu` | открыть меню бота в его личке |
| `.botinfo`, `.startbot`, `.setbotpic`, `.revokebot` | карточка бота, приветствие, аватарка, токен |
| `.logs [уровень]`, `.logchannel`, `.clearlogs` | логи файлом и канал с логами |
| `.backup`, `.backups`, `.autobackup`, `.restoredb` | бэкапы базы и расписание |
| `.update`, `.restart`, `.updatecheck`, `.autoupdate`, `.version` | обновление и перезапуск |

Привычные по другим юзерботам имена работают как алиасы: `.terminal` → `.shell`,
`.setprefix` → `.prefix`, `.setlang` → `.lang`, `.e` → `.eval`, `.p` → `.ping`,
`.h` → `.help`, `.cfg` → `.config`.

Приятные мелочи:

- `.реды` сработает как `.help` — раскладка исправляется автоматически;
- `..help` ничего не выполнит — двойной префикс экранирует команду;
- `.modules | grep loader` — фильтрация вывода любой команды;
- `.help@username` — адресация конкретному аккаунту, если их несколько.

## Как это выглядит

`.info` — карточка юзербота под баннером:

```
🪶 Сойка 1.5.0

🌟 Владелец: Имя ← ссылка на профиль
✍️ Префикс: «.»
⏰ Аптайм: 3 д. 07:22:06
🧩 Модулей: 14 · команд: 44

🔄 Нагрузка CPU: 0.4 %
👾 Нагрузка RAM: 118.6 МБ

💾 Установлен: 💎 VDS
🕸 Сборка от 19.08.2026 · исходники ← ссылка на коммит
```

Карточка настраивается: `.cfg` → **Инфо** →

- `banner_url` — картинка или гифка над текстом. Подойдёт ссылка на `.png`,
  `.jpg`, `.gif` или `.mp4`; пустое значение убирает баннер совсем;
- `custom_message` — свой текст карточки. Подстановки: `{owner}`, `{version}`,
  `{build}` (дата сборки), `{commit}`, `{source}`, `{prefix}`, `{uptime}`,
  `{cpu}`, `{ram}`, `{platform}`, `{modules}`, `{commands}`, `{brand}`,
  `{emoji}`, `{repo}`.

## Бот и его меню

Инлайн-бота Сойка создаёт себе сама при первом запуске и сразу пишет ему `/start`,
чтобы в списке чатов появилось меню. **Бот отвечает только владельцу аккаунта** —
все чужие апдейты отбрасываются на входе.

Меню в личке бота: `🗄 Бэкап`, `⚙️ Настройки`, `🌐 Исходники`. Из него включается
лог-канал, переключается язык и расписание бэкапа — без команд. Открыть заново:
`.botmenu` (или `.menu`), а `.startbot` пришлёт приветствие ещё раз.

После каждого перезапуска бот сам отмечается в личке — так видно, что он
поднялся. Если бот замолчал (например, остался висеть чужой `getUpdates`), Сойка
терпеливо перепробует опрос две минуты, а `.revokebot` перевыпустит токен через
BotFather.

## Служебные каналы

Сойка заводит их сама при первом запуске, сразу отправляет в архив и глушит —
в списке чатов они не мешаются.

| Канал | Что внутри | Настройки |
|---|---|---|
| `soika-logs` | ошибки и предупреждения потоком | `.logchannel`, уровень и частота — в `.cfg` → Логи |
| `soika-backups` | бэкапы базы по расписанию | `.backups`, `.autobackup`, `.cfg` → Бэкап |
| `soika-assets` | файлы модулей | создаётся по необходимости |

При первой установке Сойка **сама спрашивает про бэкап** — присылает в «Избранное»
карточку с кнопками и ничего не включает молча. Та же карточка открывается
командой `.backups` и кнопкой «🗄 Бэкап базы» в приветствии бота: режим
(каждый день / раз в N часов / выключить), время из пресетов `00:00…21:00`
или своё через личку бота, получатель (канал или «Избранное») и кнопка
«Сделать бэкап сейчас».

По умолчанию — **каждый день в 03:00** по времени сервера в `soika-backups`;
в канале хранятся последние 20 копий, старые подчищаются. Текстом то же самое:
`.autobackup 03:30`, `.autobackup 6h`, `.autobackup off`.

Восстановление — `.restoredb` ответом на файл бэкапа. Перед перезаписью Сойка
откладывает текущую базу в ревизию `db-<id>.json.rev1`, так что откатиться можно
всегда. Чужой файл она не примет: копия подписана id владельца, а посторонний
JSON и пустой файл отбрасываются, не тронув базу. В бэкапе лежит всё, включая
токен инлайн-бота и список доверенных — не пересылай его никому.

Лог-канал по умолчанию включён и получает записи уровня `ERROR` и выше пачками
раз в 15 секунд. Уровень (`DEBUG`…`CRITICAL`) и частоту можно поменять там же.

## Обновления

Сойка сама следит за репозиторием: первая проверка проходит через две минуты
после запуска, дальше — раз в час. Когда выходит новая версия, в личку бота
приходит карточка:

```
[баннер]

🪶 Вышло обновление Сойки

🕸 Версия: 1.4.0 → 1.5.0
📦 Новых коммитов: 2

📝 Что изменилось:
▫️ Версия 1.5.0
▫️ README переписан от корки до корки

[⬇️ Обновить]  [🚫 Позже]
[📖 Коммиты]
```

Нажал «Обновить» — Сойка подтянет изменения, поставит новые зависимости,
перезапустится и пришлёт отчёт: с какой версии на какую и что именно приехало.
То же самое делает команда `.update`, а `.upcheck` проверяет обновления сразу,
не дожидаясь часа.

С включённым автообновлением (`.autoupdate`) она не спрашивает, а сама пишет
«обновляюсь» со списком изменений и присылает отчёт после перезапуска.

Настройки — `.cfg` → **Обновление**: `check` (проверять или нет), `interval`
(как часто, минут), `auto_update`, `banner_url`.

## Баннеры

У каждого модуля свой баннер в общем стиле — их видно в приветствии, в
`.help <модуль>`, при установке модуля, в меню бэкапа, в уведомлении об
обновлении и в `.info`. Картинки лежат в [`assets/`](assets/) и собираются одним
скриптом:

```bash
python assets/make_banners.py
```

Заголовок баннера совпадает с названием модуля, так что раздел и картинка
читаются как одно целое. Свой баннер модулю задаёт строка `# meta banner:` в его
шапке, а баннеры `.info` и уведомления об обновлении меняются через `.cfg`.

## Как написать модуль

Модуль — это один `.py` файл с классом-наследником `loader.Module`:

```python
from .. import loader, utils


@loader.tds
class ПриветМод(loader.Module):
    """Здоровается и умеет считать"""

    strings = {
        "name": "Привет",
        "hello": "👋 <b>Привет, {}!</b>",
    }
    strings_en = {"hello": "👋 <b>Hi, {}!</b>"}

    config = loader.ModuleConfig(
        loader.ConfigValue(
            "emoji",
            "👋",
            "Каким смайликом здороваться",
            validator=loader.validators.String(max_len=4),
        )
    )

    async def client_ready(self, client, db):
        """Вызывается один раз при загрузке"""

    @loader.command(alias="пр")
    async def hellocmd(self, message):
        """[имя] — поздороваться"""
        name = utils.get_args_raw(message) or "мир"
        await utils.answer(message, self.strings["hello"].format(utils.escape_html(name)))

    @loader.watcher(only_pm=True, no_commands=True)
    async def watcher(self, message):
        """Реагирует на входящие в личке"""
```

Шапка модуля понимает метаданные:

```python
# meta developer: @username
# meta banner: https://example.com/banner.mp4
# meta description: Короткое описание для каталога
# requires: aiohttp
```

`banner` (или `pic`) показывается картинкой при установке модуля и в
`.help <модуль>`.

Полезное:

- `# requires: aiohttp pillow` в шапке файла — зависимости поставятся сами;
- `@loader.loop(interval=60, autostart=True)` — фоновая задача;
- `await self.inline.form("текст", message, reply_markup=[{"text": "Кнопка", "callback": self.cb}])` — кнопки;
- `await self.inline.gallery(message, ["url1", "url2"])` — листаемая галерея;
- `self.get("ключ")` / `self.set("ключ", значение)` — своя секция в базе;
- `@loader.owner`, `@loader.everyone`, `@loader.group_admin` — права на команду.

Установить свой модуль: отправь `.py` файл в любой чат и ответь на него
`.loadmod`.

## Устройство

```
soika/
├── main.py          запуск, аккаунты, главный цикл
├── auth.py          QR-логин, вход по номеру, 2FA, сессии
├── client.py        Telethon-клиент с кэшем сущностей
├── database.py      JSON-база с атомарной записью и ревизиями
├── loader.py        загрузка модулей, декораторы, зависимости
├── dispatcher.py    разбор команд, фильтры, ratelimit, grep
├── security.py      owner / sudo / support и маски прав
├── translations.py  языковые паки и строки модулей
├── compat.py        совместимость с чужими модулями
├── inline/          свой бот: формы, галереи, списки, ЛС
├── web/             веб-установщик и панель
└── modules/         встроенные модули
```

Данные — сессии, `config.json`, `db-<id>.json`, `loaded_modules/` — лежат рядом с
кодом и в git не попадают. Каталог можно перенести аргументом `--data-root`.

## Вопросы и ответы

**Забанят ли аккаунт?** Юзерботы Telegram не приветствует. Риск снижают простые
вещи: не спамить, не раздавать `.sudo` посторонним и не ставить на аккаунт,
который жалко потерять.

**Нужен ли свой сервер?** Нет, но с ним удобнее — юзербот работает, только пока
запущен процесс. Подойдёт любая VDS, Termux на телефоне или домашний компьютер.

**Что если бот не создался?** У BotFather лимит 20 ботов на аккаунт. Удали
лишнего и перезапусти Сойку — она попробует снова.

**Как перенести на другой сервер?** Скопируй каталог с данными (`config.json`,
`soika-*.session`, `db-*.json`, `loaded_modules/`) — всё состояние в них.

**Как откатиться?** `.backup` присылает копию базы файлом, `.restoredb` ответом
на этот файл возвращает состояние обратно.

**Работают ли модули от других юзерботов?** Да, написанные под Hikka, FTG,
GeekTG и Dragon ставятся без правок — импорты подменяются на лету.

**Как посмотреть, что сломалось?** `.logs error` пришлёт файл с ошибками, а
служебный канал `soika-logs` копит их постоянно.

- Юзербот работает от имени твоего аккаунта — команды видны так, будто их пишешь
  ты сам.
- `api_id` и `api_hash` личные, они хранятся только в `config.json` на сервере и
  никуда не отправляются.
- Веб-панель слушает порт наружу и закрыта одноразовым токеном из логов. На
  сервере лучше закрыть порт фаерволом и ходить через SSH-туннель.
- `.e` и `.shell` выполняют произвольный код и команды системы — держи их только
  для себя.
- `.update` работает, только если Сойка установлена из git-репозитория с remote.
